# refemu — differential tester (original vs. port)

Runs the original game code (`orig/unpacked/SH.coff`) in unicorn with high-level emulation
of Allegro 3.11 / DJGPP libc and checks that its game state matches the port's at every
point where the environment (input, timers) can change.

    re/refemu/difftest.sh REPLAY [--dump A-B] [--keep-going] [-- game args, e.g. /judge]

1. The port runs the replay headless with `--sync-log`: every call that may change the
   environment is bracketed (`sys_sync_enter/leave`, outermost bracket only). On entry the
   port hashes the canonical game state (CRC-32 per section), on exit it writes a record:
   kind, return value, hashes, `key[]`, key buffer, pad 0 bits, mouse, `g_tick/g_fps/g_frames`.
   Kinds: `i` sys_idle (wait_tick), `p` sys_poll, `V` vsync/set_pallete, `R` rest,
   `F` fades, `K` readkey, `J` install_joystick, `B` random seed (biostime).
2. `refemu.py` runs `main()` of the original. HLE functions that sync (vsync, rest, fades,
   readkey, ...) and the busy-wait sites listed in `sites.tsv` consume the next record:
   the kinds must match, the emulator's state hashes must equal the port's, then the
   record's environment is copied into emulated memory.
3. On a mismatch, rerun with `--dump N` (N = record index): the port then stores the full
   canonical state for that record and the report lists the differing fields.

Canonical state = the sections in `layout.json` (generated with `src/game/sync_state.c` by
`re/tools/gen_sync.py` from `re/ghidra/types.h`): DOS layout, raw bytes, pointers replaced by
(datafile object, offset). Add globals there when they get names.

`sites.tsv`: the original busy-waits on `g_tick`/`key[]`; the port calls `wait_tick()` in
the same loops. Each site is the address in the original that corresponds to the port's
call (loop back-edge, or body start when the port waits there). `p?15` = only while
`key[15]` (TAB) is down. A missing site shows up as a stall with the hot loop's address.

Besides the state, every record carries a hash of the game-level drawing and sound calls
made since the previous record (`src/game/calllog.h`, generated by `re/tools/gen_calllog.py`;
emulator side: `CALLS` in `refemu.py`). Calls are logged as text, e.g.
`draw_rle_sprite #c1 #d3.24 116 18` (`#scr` screen, `#dF.N` datafile object, `#cN` N-th
created bitmap/RLE sprite, `pal:CRC` palette contents); with `--dump` the report shows the
first differing call. So positions, sprites, colours, texts, samples and music are checked
too, not only the game state.

`--pixels` (also `REFEMU_OPTS=--pixels` for `regress.sh`/`fuzz.sh`): the emulated original
draws with Allegro 3.11's own code (a memory bitmap as screen, Allegro's linear 8-bit
vtable, HLE `malloc`), and the screen and palette are compared at every record as well.
A mismatch writes `frame_N.png` (original | port | differing pixels) next to the log.

`UB_INIT` in `refemu.py`: a few functions read uninitialized locals ("still held" latches).
Their real value depends on what earlier frames left on the stack; the port defines them as
1 and the emulator writes 1 into those slots at function entry.

Drawing, sound and MIDI are otherwise no-ops in the emulator (game logic never reads pixels it
drew); pixel collision (PPCOL) reads the real datafile bitmaps, `_getpixel/_putpixel` run
natively (bitmaps use a flat GDT data selector).
